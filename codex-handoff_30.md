## The big thing: character deck viewer (character-deck.js)

New module, wired into `characters.js`'s GM and player detail panes (previously empty placeholders since S10). Renders a selected Character entity as 5 sections of small parchment "cards" (mirroring `.codex-entity-card`'s visual identity, scaled down) sitting in dark "trays" — the physical Daggerheart-cards-on-the-table metaphor, confirmed via several mockup iterations before building (mockup files aren't committed, just shown in-conversation).

**Sections, top to bottom:**
1. **Heritage + Conditions** — share one row via a draggable split (60/40 default). Heritage: always exactly 2 Ancestry cards (First/Second feature groups — same ancestry name twice if only one ancestry picked) + 1 Community card. Conditions: linked-to-Codex-entity or free-text custom entries, add/remove.
2. **Class** — Class card + Subclass card share their own row within this section (40/60 default), only when both exist (lone card just fills normally otherwise). Live Tier select in the section header governs the Subclass card's cumulative-tier text.
3. **Abilities** — tabbed: Active / Vault / Experience / Beastforms (Beastforms only if Class == "Druid", exact-name match verified against live SRD data). Active/Vault backed by `cards.abilityIds` (unchanged, still owned by the Codex tab's existing picker) + new `cards.vaultAbilityIds` (a SUBSET of abilityIds — Active is derived as "abilityIds minus vaultAbilityIds", never stored separately, so the two can't drift). Experience is wholly new (`cards.experiences`, freeform name+text, no Codex link — see below). Beastforms is read-only reference, grouped by Tier.
4. **Equipment** (renamed from "Inventory" mid-session) — `cards.equipment`, linked-or-custom, qty.

**Architecture — read this before touching this file:**
- **Direct-write, not draft/Save-Cancel.** Every add/remove/swap/reorder writes straight to Firestore via `patchCards(entity, patch)` (merges into `entity.cards`, writes whole object). Deliberately different from `character-cards.js`'s build-time editor (draft object, Save/Cancel commits once) — flagged explicitly to Gregg before building given the S9/S10 history of two editing surfaces causing confusion; the split here is build-time (Codex tab: ancestry/community/class/subclass/abilityIds/badgeColor) vs. play-time (this module: subclass tier, Active/Vault split, Conditions, Equipment, card order) — non-overlapping slices of `cards`, not a duplicate.
- `resolveEntityStatBlockMarkdown(entity, ctx, tierFilter)` — new export from **codex.js** (not character-deck.js), used by every card's body text. Does Details + tier-filtered Features + lore-item leftover text, with a raw-lore-content fallback for non-templated types (Conditions, Items, Consumables — these have no `templates.js` schema at all). This is MORE complete than `character-cards.js`'s own `slotStatMarkdown` (which only reads `entity.details`/`entity.features` directly, skipping lore items — fine for the build-time editor's verification-only slots, wasn't fine for the deck's actual reference cards).
- `cleanCardMd()` + `stripHeadingLines`/`stripSections`/`stripBulletLines` (character-deck.js) — deck-card-only markdown post-processing, NOT touching `resolveEntityStatBlockMarkdown` itself or the Codex tab's Lore tab display:
  - Strips bare `### Details`/`### Features` heading lines everywhere (content stays).
  - Ancestry cards additionally strip `### First`/`### Second` (redundant with the card's own titleSuffix).
  - Class cards additionally strip whole `### Background`/`### Connection` sections (heading + question list, not just the heading).
  - Every card type strips Details bullets that duplicate its own meta line/badge (e.g. Ability cards drop the Domain/Level/Type/Recall bullets since those are already the meta line) — see `stripBulletLabels` at each call site for the exact per-type list. **Verified `humanizeKey('hp')` actually produces `"Hp"` not `"HP"`** before wiring the Class card's strip list — don't assume humanizeKey output, check it.
  - Items/Consumables additionally strip a lone `### Details` / `- **Roll:** N` pattern (hand-authored, not synthesized — these categories have no schema) via `stripLoneRollDetails`.
- **Card structure** (`buildMiniCard`): header row = `.character-deck-card-title-group` (name h3 + Codex link, right of the name — was left, was bottom-left corner, moved twice per Gregg's follow-ups) opposite `.character-deck-card-controls` (swap/remove icons, top-right). Tier/Level badge normalized to bottom-right on every type that has one (Ability's Level, Weapon/Armor/Beastform's Tier) — same slot regardless of type, deliberate "fixed landmark when scanning across cards" call. Codex link on every card type except Experience (never Codex-backed) and unlinked custom Condition/Equipment entries.
- **Split rows** (`buildSplitRow`) — Heritage/Conditions and Class/Subclass. Draggable vertical divider, Pointer Events (works the same touch vs mouse), split fraction via a `--split-fraction` CSS custom property on the row (NOT inline flex-basis on the panes — keeps specificity low enough for the narrow-container fallback to override with a plain class rule, no `!important`). `.character-deck` has `container-type: inline-size`; below 420px of the deck's OWN width (not viewport — deliberate, since the deck sits behind a fixed 300px list-pane in a layout where viewport width doesn't track available width) the split stacks to a column and hides the handle. Split fraction is **session-only** state (`state.characterDeckHeritageConditionsSplit`/`characterDeckClassSplit`) — a viewing preference, not campaign data, resets on reload.
- **Drag-reorder** (`enableCardReorder`) — Abilities' Active/Vault/Experience tabs + Equipment. Same lazy-CDN SortableJS pattern as codex.js's Gallery/Lore reorder and admin.js's Sources reorder (own local `loadSortable()` wrapper per module around the shared `state.sortableModulePromise` — that's the established convention, not a shared import). `forceFallback:true`, `filter:'.character-deck-add-slot'` + `preventOnFilter:false` so the add-slot stays put/un-draggable without losing its own click handler. **Persistence is just writing the reordered array back to Firestore** — display order already IS array order for `abilityIds`/`vaultAbilityIds`/`experiences`/`equipment`, so no new schema field, no localStorage; it survives reloads because it's the same data everything else reads. Active-tab reorder reconstructs `abilityIds` as `[newActiveOrder, ...vaultIds]` (vault items' relative order untouched); Vault tab writes `vaultAbilityIds` directly.
- **Header** (`buildDeckHeader`) — badge dot + name. Player view (own owned character, editable): "Edit in Codex" link, top right → jumps to Codex tab AND enters edit mode. GM view: "View in Codex" in the same spot → view mode only, no edit mode entered.

**New `cards.*` fields** (all under the existing whitelisted `cards` object — no `firestore.rules` change needed): `vaultAbilityIds`, `conditions` (`[{id, entityId|null, label, note}]`), `equipment` (`[{id, entityId|null, label, qty}]`), `experiences` (`[{id, name, text}]`, always freeform, no entityId — no Codex entry ever backs one).

**`character-cards.js` changes** (the Codex-tab build-time editor): exported `cumulativeTierKeys`, `buildFloatingPickerPanel`, `openAbilityPickerPopup` (reused directly by character-deck.js — same Add-ability popup in both places, not a duplicate). New `buildExperiencesEditor` (flat add/remove list, no Active/Vault split, same shape as the existing Abilities picker) wired into `buildCharacterCardEditor` right after Abilities — Experiences are now editable from BOTH the Codex tab's edit form and the deck viewer's Experience tab, sharing one add popup (`openExperiencePickerPopup`, lives here not in character-deck.js).

**`templates.js` schema additions** (confirmed against the live `seansbox/daggerheart-srd` raw JSON before adding, not guessed): `recall` (abilities), `damage` (weapons), `examples` (beastforms) — all three existed in the raw SRD source but fell into generic leftover bullets, never mapped into structured `details`. **Gregg needs to re-run Admin → SRD import → "Update entries"** to backfill these onto already-imported entities — I can't trigger that myself (needs live GM auth in the browser). Not confirmed done as of this handoff.

## The CSS debugging saga (worth reading before touching `.character-deck-card h3`)

Four rounds of "name header not top-aligned" follow-ups, each a real distinct bug, found by successively better evidence (plain description → screenshot → devtools computed-styles panel):
1. Flex row + `align-items:flex-start` (name/controls shared a row properly).
2. `line-height:1` (Comfortaa's baked-in vertical metrics).
3. Font-family switch to `var(--font-body)` (Comfortaa vs. Inter ascent-metrics mismatch between the name and the icons next to it — a genuine two-font problem, not fixable by tweaking one side).
4. **The actual root cause**, found via Gregg's devtools Computed panel: `.admin-card h3:first-of-type` (styles.css ~1181, specificity 0,2,1) was beating `.character-deck-card h3` (0,1,1) on `margin-top`, because `.characters-detail-pane`/`.characters-player-selected` both carry the shared `admin-card` class from elsewhere in the app. Same rule's `text-transform:uppercase` was ALSO leaking through uncontested (not a specificity loss — the card's h3 rule just never declared that property at all). **Fixed by chaining three real ancestor classes** (`.character-deck .character-deck-tray .character-deck-card h3`, specificity 0,3,1) to beat every `.admin-card h3*` variant regardless of source order, and explicitly declaring every property those rules touch.

Lesson for next time this kind of "looks right in code but wrong on screen" bug shows up: **ask for the devtools Computed panel early**, not just a screenshot — the screenshot alone cost 3 guess-and-check rounds that the computed-styles panel resolved in one.

Also fixed in the same saga: descender clipping (`g`/`y`/`p`/`q`/`j` cut off) — `line-height:1` was giving zero room below baseline against `overflow:hidden`; bumped to `1.2`, safe now that the actual top-gap cause (the admin-card leak) is fixed.

**Global side effect, not deck-specific:** "do not indent bullet lists" → tried `list-style-position:inside` (wrong — collapsed wrapped-line hanging indent to flush-left) → corrected to default `outside` + `1.2em` padding-left (small indent, correct hanging-indent behavior for wrapped lines). This is a **global** `ul, ol` rule (markdown.js's `renderMarkdownInto` has no dedicated wrapper class, fills whatever container class the caller passes — `.lore-item-body`, `.character-deck-card-body`, `.msg-text`, etc.), so it affects every markdown-rendered surface in the app, not just the deck. Worth a spot-check on the Lore tab / chat messages if anything there looks different now.

## Messages tray fix (small, unrelated to the deck)

Real bug found while investigating an auto-expand question: `renderMessagesTray()`'s tail unconditionally did `body.scrollTop = body.scrollHeight` for both branches — correct for the thread-chat panel (oldest-first, newest at bottom) but wrong for the Campaign digest, which sorts **newest-first** (top) — every render was pinning the digest to its OLDEST entry. Campaign branch now returns early with `body.scrollTop = 0`.

Auto-expand-on-new-content (`maybeAutoExpand`, called from `onMessagesData` on every threads/notifications snapshot) already existed and was traced/confirmed correct for BOTH: player campaign-notification unread, AND GM auto-expand when any player sends a PM (listeners are session-wide via `attachMessagesListeners()` at login, not tab-scoped, so this fires regardless of which app tab the GM is viewing). Gregg confirmed the PM case working live. GM's Campaign tab itself has no unread concept by design (rules only let a recipient flip `seenAt`, GM is never a recipient) — not a bug, an S6 decision.
